# Database

PostgreSQL 17 + PostGIS 3.7 (`postgis/postgis:17-3.7`), run with Docker Compose.

## Roles (least privilege)

Created once by
[`infrastructure/docker/postgres/initdb/20-roles.sh`](../../infrastructure/docker/postgres/initdb/20-roles.sh)
when the data volume is first initialised.

| Role (env var)     | Privileges                                                     | Used by                 |
| ------------------ | -------------------------------------------------------------- | ----------------------- |
| `POSTGRES_USER`    | Superuser                                                      | Init and emergency only |
| `DB_MIGRATOR_USER` | `CREATE` on schema `public`; owns all application tables       | `migrate` service only  |
| `DB_APP_USER`      | `SELECT/INSERT/UPDATE/DELETE` on migrator-owned tables, no DDL | API runtime             |

Hardening applied by the init script:

- `CONNECT` revoked from `PUBLIC` on every database. App and migrator can only reach the
  application database, not `postgres`, `template1` or `template_postgis`.
- `CREATE` on schema `public` revoked from `PUBLIC`.
- Default privileges grant the app role DML on future migrator-created tables and sequences.
- `postgis_topology` (installed by the image, unused here) is dropped, and the database
  `search_path` is reset to the default.

These guarantees are checked by `tests/integration/test_database.py`.

> **Init scripts only run on an empty volume.** After changing `20-roles.sh` locally, recreate
> the volume with `docker compose down -v`, which **deletes all local data**. Production role
> changes must be applied with a reviewed SQL script, never by recreating the volume.

## Migrations

Alembic, in `apps/backend/migrations`. The `migrate` Compose service runs `alembic upgrade head`
as the migrator role before the API starts; the API waits for it to finish successfully.

```bash
cd apps/backend
.venv/Scripts/alembic revision --autogenerate -m "describe change"   # create
.venv/Scripts/alembic upgrade head                                   # apply
.venv/Scripts/alembic check                                          # models == DB?
```

Rules: review every autogenerated migration; never edit an applied migration; destructive
changes (drop column/table) need an explicit, reviewed migration and a backup first.

## Schema and seed data

- Data model and planned entities: [`schema.md`](schema.md); conventions:
  [ADR 0003](../architecture/adr/0003-database-conventions-and-regions.md).
- Reference regions (India → Maharashtra → Ratnagiri/Raigad, 24 talukas, 34 places) are
  loaded by an **idempotent** seed, not by migrations:

```bash
docker compose run --rm migrate python -m app.seed            # apply (as migrator role)
docker compose run --rm migrate python -m app.seed --dry-run  # report only, rolled back
```

The seed upserts names/kind by parent + slug, never deletes or deactivates rows, and never
touches `lgd_code`, `centroid` or `is_active`. Seed content (`app/seed/regions.json`) must be
verified against the Local Government Directory before production; Hindi place names, LGD
codes and coordinates are intentionally empty until sourced authoritatively.

- Readiness (`/api/v1/health/ready`) reports `migrations: fail` when the database is not at
  the migration head shipped with the running build.

## Network exposure

- `compose.yaml` (production-like) publishes **no** database port.
- `compose.override.yaml` (dev) publishes it on `127.0.0.1:5432` only.

## Backup and restore (local / single host)

Verified 2026-11-20 against the dev stack. Run from the repository root; `backups/` is gitignored.

```bash
# Backup (custom format, compressed)
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > backups/konkan-$(date +%Y%m%d-%H%M%S).dump

# Restore into a NEW database (never restore over the live one without a fresh backup)
docker compose exec -T db sh -c 'createdb -U "$POSTGRES_USER" konkan_restore && \
  pg_restore -U "$POSTGRES_USER" -d konkan_restore --exit-on-error' < backups/<file>.dump
```

On Windows Git Bash, prefix commands with `MSYS_NO_PATHCONV=1`. Dumps contain personal data
once users exist: store them encrypted and never commit them. Automated, off-host backups are
planned for Sprint 10.
